# 三至五分钟演示提纲

## 演示前

源码版本先构建：`moon build --target js --release`。运行包有 dist 时只需 Node.js。运行 `npm run demo`，四个结果均符合预期才开始录屏。录屏中故意出错的案例返回 1 是正确演示结果。

## 建议顺序

1. 约 30 秒：说明真实问题——译文合入后可能丢失参数或缺少复数槽位。介绍这是 MoonBit 编写的开发期检查工具。
2. 约 40 秒：中文示例与 POT 对照，通过且展示三条有效译文。
3. 约 60 秒：broken 示例，指出参数类型变化、命名字段缺失和复数槽缺项的文件行号。
4. 约 40 秒：展示 JSON 报告和 CLI 退出码，说明如何接入 CI。
5. 约 30 秒：复数例子，明确有限采样区间、短路与异常处理，不称为数学证明。
6. 约 40 秒：打开核心模块、测试证据与 CI 页面，展示 MoonBit 承担算法、Node 只做输入输出。若 CI 尚未运行，明确说明。

## 可直接使用的讲述要点

本项目处理 PO/POT 翻译文件。它既可嵌入 MoonBit 项目，也能通过命令行检查实际文件。当前支持 C printf、Python percent 和 brace 格式参数，并能对照模板和检查复数规则。所有检查核心用 MoonBit 实现。已有同类 gettext 工具，我们的价值是 MoonBit 生态的实现和接入，不能宣称全球首创或完全替代 GNU gettext。
