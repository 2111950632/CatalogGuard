# 完善事项与参赛步骤

截至 2026-10-13，本项目已有可运行的 MoonBit 检查核心。0.1.1 继续修复边界问题，补齐发布包的独立调用验证、一条命令验收和演示。参赛准备应优先完成真实发布与验收证据。

## 按优先级处理

| 优先级 | 事项 | 完成标准 |
|---|---|---|
| P0 | 上传公开 GitHub 仓库 | 远端 main 显示最新代码和完整提交历史 |
| P0 | 跑通 GitHub Actions | 核心、CLI、独立 consumer、polib 与 GNU 对照均通过，保存真实运行链接 |
| P0 | 发布 Mooncakes | 本人登录、命名空间核对、发布 0.1.1，再从注册表新建项目下载调用 |
| P0 | 核对完整章程并报名 | 确認报名通道、截止时间、作者身份、AI 辅助说明和主办方要求的材料 |
| P1 | 录制演示并整理答辩 | 可复现地展示正常、出错、JSON、复数边界和测试证据 |
| P1 | 扩展真实语料 | 更多语言的复数目录和参数风格；数据许可与结果均记录 |
| P2 | 后续功能 | 中文诊断、编辑器接入、更多格式扩展；先确定支持边界与用例，再开发 |

不建议临近报名增加自动翻译或 MO 编译等大范围功能。当前应证明已有能力的正确性和实际可用性。

## 逐步执行

1. 打开本地项目，执行 `npm run verify`。先解决失败步骤。此流程包含 37 个核心测试、19 个 CLI 测试和独立压缩包 consumer 验证；实际数量以最新输出为准。
2. 使用正常 GitHub 登录流程上传：在保留 `.git` 的本地项目目录执行 `git push origin main`。不要仅通过网页逐个上传文件，否则不能保留开发提交历史。下载运行包者可按 history/README.txt 恢复 Git bundle。
3. 打开仓库的 Actions 页，等待 Check SZS 的实际结果。失败时打开失败步骤日志；修复并再次上传。成功后下载 szs-verification 验证产物。没有实际成功运行时，不写“CI 已通过”。
4. 在 Mooncakes 注册或登录本人账号，确认可用命名空间是否为 `2111950632`。不一致时先同步修改模块名、依赖引用与文档，再完整验收。然后依次 `moon login`、`moon package`、`moon publish --dry-run`、`moon publish`。
5. 发布后在一个新目录用 `moon add 2111950632/szs` 下载，再写 consumer 调用 parser/check/report，保存实际包版本和链接。本地 workspace 的成功不能代替这一步。
6. 核对比赛最新完整章程，填写报名。官网当前公开安排写明十月场报名和提交截止为 10 月 31 日；以最新完整通知为准。一次确认队伍/参赛者信息、公开仓库、项目说明、许可证、AI 使用说明、示例、测试证据与包链接。
7. 用 `npm run demo` 排练，按 DEMO.md 录制三至五分钟演示，说明检查范围和限制。提交材料后保存回执或确认记录。

## 仍需本人或外部服务完成

GitHub 与 Mooncakes 的账号认证、报名表填写和演示录制需要本人参与。GNU 工具本机下载受网络限制，CI 已设置必须执行其对照；尚未执行时应保留未验证状态。完整飞书章程在本次读取工具中不可访问，最后由参赛者核对，不能仅凭项目代码认定资格。
