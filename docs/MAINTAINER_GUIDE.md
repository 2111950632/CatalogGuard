# 维护者讲解与复审准备

日期 2026-10-22，版本 0.2.2。先阅读 PROJECT_QUALITY.md 的边界，再逐项运行 examples/project-quality/README.md 的命令；需要能够说明下面的设计并现场解释输出。

## 核心数据路径

PO 解析器保留字段范围，产生 Catalog/Entry/Translation。markup.mbt 用带资源预算的递归片段解析，区分 HTML/XML 的标签、属性、实体和闭合规则；把忽略译文文本后的树编码为长度前缀合同，将同级子树和属性排序，使合法重排不影响相等比较，同时保留属性与子树绑定。

consistency.mbt 读取 Language 并规范化大小写/分隔符，按语言、上下文、源文建索引。复数源文、同复数源文的全部译文槽位、flags 及可选逆向源文分别保留至多五个见证。见证必须同时位于另一个文件且比较值不同；忽略上下文时，同一文件里的多个条目也不能被首条遮蔽。每个当前条目每条规则最多一项，保留双方范围；warning 供人工审阅，strict 或升级规则可阻止合入。

五个见证的理由：保留第一条；查询与首条同文件时，保留该文件外的两种不同值足够判断；查询与首条同值时，保留该值外的两个不同文件足够判断；文件和值均不同时可直接用第一条。用 768 个正向和 729 个逆向小项目与朴素比较器核对，不能把有限输入排列当作完整形式证明。

project.mbt 组合原有单文件校验、新的标记和跨文件校验，再统一应用规则严重性和退出策略。protocol.mbt 将结构化结果传递给宿主；CLI 只做文件选择和 UTF-8 读写。

## 评审可现场提问的边界

- 为什么要 opt-in？源文中的普通 `<Error>`、数学表达式不一定是标记，自动猜测容易误报。
- 为什么允许同级重排但保留祖先？不同语言可调整词序；将强调或链接移到另一个父元素则改变结构。仅数标签数量不能区分二者。
- 为什么 href 默认不可翻译而 title 可以？href 往往是程序资源合同，title 是显示文本；项目可显式配置例外。
- 为什么不根据文件名猜语言？路径结构不统一，错误分组会把法文和中文判为译法冲突；缺失 Language 时明确告知跳过。
- 为什么 HTML 的 `&#128;` 与 XML 不同？HTML 标准对这类 C1 数字引用重映射为显示字符，例如欧元符号；XML 保留原码点。合并两种规则会使受保护属性误判，独立 HTMLParser/ElementTree 属性对照与正式回归验证这项差别。
- warning 是否等于错误翻译？不等于。同源词可能有意使用不同术语，需人工审阅；严格策略可要求先解决。
- 是否替代 Translate Toolkit？否。实现的是 MoonBit 中可嵌入的固定质量检查范围，已有功能和实测差异公开；不提供其全部格式转换或语言服务。
- 能否展开外部实体、修复 HTML 或验证 schema？这些不在本版本范围，明确拒绝或不宣称验证，不请求外部实体网络。

## 对照赛事要求

本地 `moon info` 后运行 `node --test tests/interfaces.mjs` 和 `node scripts/check-interfaces.mjs`，核对公开接口。工具链可能把内建 Int 输出为 Int32，检查只接受这项等价写法；其他公开接口变化仍需审阅并提交生成文件。遇到未来新增的泛型或同名自定义类型时，检查保守采用精确比较。CI 的 core-verification.txt 保存编译、格式和接口步骤输出。
